## Source
- Kaggle: https://www.kaggle.com/datasets/ealaxi/paysim1 (title: "Synthetic Financial Datasets For Fraud Detection")
- Expected file: `PS_20174392719_1491204439457_log.csv` (name as commonly distributed; confirm on your download)
- Paper: Lopez-Rojas, Elmir, Axelsson, "PaySim: A financial mobile money simulator for fraud detection", EMSS 2016.
- **This is simulated data**, generated by the PaySim simulator from aggregated statistics of one month of logs from a mobile-money
  service. It is **not** real bank-customer data, and results on it do not transfer to real-world fraud performance.

## How to obtain it (Windows)
Primary path (manual, no credentials in code): sign in to Kaggle in a browser, open the page above, click Download, unzip, and move the CSV to
`C:\Projects\AIML-01-Fraud-Detection\ml\data\raw\`.
Optional CLI path (**UNVERIFIED**: not run by the author): `python -m pip install kaggle`, create an API token on your Kaggle account page and save it as
`%USERPROFILE%\.kaggle\kaggle.json` (never inside the project, never in Git), then
`kaggle datasets download -d ealaxi/paysim1 -p ml\data\raw --unzip`.
Verify the file, do not assume: `Get-Item ml\data\raw\*.csv | Select-Object Name, Length`, then `Get-FileHash -Algorithm SHA256 ml\data\raw\<file>.csv`.
`ml\data\raw\*` is git-ignored (only `.gitkeep` is tracked).

## Facts taken from public descriptions (NOT yet confirmed on the real file)
- 744 time steps, 1 step = 1 hour (30 days); types CASH-IN, CASH-OUT, DEBIT, PAYMENT, TRANSFER (hyphen/underscore spelling unconfirmed).
- Columns: step, type, amount, nameOrig, oldbalanceOrg, newbalanceOrig, nameDest, oldbalanceDest, newbalanceDest, isFraud, isFlaggedFraud.
- Fraud behaviour in the simulation: take over an account, transfer funds out, then cash out. `isFlaggedFraud` flags transfers above a fixed amount.
- Balance information is not available for merchant (M-prefixed) destinations.
- **Leakage warning in the dataset description:** fraudulent transactions are cancelled, so the balance columns behave unlike real data and
  should not be relied on. This project therefore excludes them by default (`--feature-set base`) and tests the alternatives explicitly
  (`pre_balance`, `all_balance`); see `docs/feature_engineering.md`.
- One third-party mirror lists 6,362,620 rows and 11 columns. Unconfirmed.

## Limitations to state in your report
Simulated; one month; only account names and a time step (no device, card, location or customer attributes, so no account-device-card graph); fraud
follows the simulator's rules; `isFlaggedFraud` is the output of an existing rule and is never used as a feature.

## What the code reads
`ml/train.py` reads only the columns the chosen feature set needs plus `isFraud` (see `ml.pipeline.schema.FEATURE_SET_INPUTS`); `isFlaggedFraud`
and extra columns are never loaded. It rejects missing/non-CSV/empty files, missing columns, non-numeric or negative numeric columns, targets other
than 0/1, single-class targets, and splits without both classes. EDA (`ml.eda.analyze`, `ml/eda/inspect_dataset.py`) reads all 11 columns.
